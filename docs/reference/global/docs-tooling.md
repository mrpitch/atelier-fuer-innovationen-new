# Docs tooling

Every doc under `docs/` carries the Home `docs` skill's frontmatter contract: `type`, `title` and `description` required, plus `tags`, `status` and `last_reviewed`. `type` matches the Diataxis quadrant its folder names — `tutorials` → `tutorial`, `how-to` → `how-to`, `reference` → `reference` (nested reference subfolders too, e.g. `reference/css/`), `explanation` → `explanation` — and ADRs in `docs/adr` carry `type: adr`. The generated index (`docs/index.md`) and every section `README.md` are exempt; neither carries frontmatter.

## `docs:check`

`scripts/docs-check.mts` walks a docs directory — the real `docs/` by default, or a directory passed as its one argument — and reports every doc missing a required field or whose `type` doesn't match its folder, naming the file, the field and why, then exits non-zero if anything failed. `pnpm docs:check` runs it against the real `docs/` directory.

It splits each file's frontmatter with `splitDocument`, imported from the content domain's public API (`src/lib/content/index.ts`, [Folder structure](folder-structure.md)) — the same YAML-frontmatter parser the content loader uses ([Content layer](../content/content-layer.md)), so the repo has one frontmatter parser and no `gray-matter` dependency. Like `content-check.mts`, it runs under plain Node with `scripts/ts-extension-loader.mjs` registered, so it can import that module by its normal extensionless relative path.

## `docs:lint`

`pnpm docs:lint` runs [`markdownlint-cli2`](https://github.com/DavidAnson/markdownlint-cli2) over `docs/**/*.md` plus the root `README.md`, `AGENTS.md` and `CLAUDE.md`, configured by `.markdownlint-cli2.jsonc`. `PRODUCT.md` and `DESIGN.md` opt out: both are generated by the `/impeccable` and `/docs write product` skills under their own frontmatter dialect and heading conventions, not this one. MDX content stays out of it too — `eslint-plugin-mdx` lints `.mdx` ([Content layer](../content/content-layer.md#mdx-lint)).

The config turns off three default rules that fire on every doc here, not on a real problem:

| Rule                               | Why it's off                                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| `MD013` (line length)              | Prose isn't reflowed to a column width; prettier's default `proseWrap` is `preserve`.             |
| `MD041` (first-line heading)       | `AGENTS.md` and `CLAUDE.md` are agent instructions, not Diataxis docs, and don't open with an H1. |
| `MD010` (hard tabs) in code blocks | Fenced code examples keep the project's own tab indentation (prettier's `useTabs`).               |

`MD025` (single top-level heading) keeps its default `front_matter_title` detection turned off (`front_matter_title: ""`): every doc here has both a frontmatter `title` and its own body H1, and without this setting markdownlint counts the frontmatter title as a heading and flags the real H1 as a duplicate.

## `docs:index`

`pnpm docs:index` regenerates `docs/index.md` with the Home `docs` skill's own generator (`~/.claude/skills/docs/scripts/generate-index.ts`), run via `npx tsx`. Run it after adding, moving or removing a doc. `agents.yaml`'s `commands.docsIndex` points here so the skill's own `docs index` operation prefers the project's wrapper over invoking the script path itself.

## Pre-commit

`.lintstagedrc.mjs` runs `docs:lint` then `docs:check` once per commit — not per staged file, the same reasoning as `content:check` — whenever a staged file matches `docs/**/*.md`, `README.md`, `AGENTS.md` or `CLAUDE.md`. `markdownlint-cli2` always unions its own config's `globs` with whatever paths it's given, so passing it just the staged files wouldn't narrow its scope anyway.

## CI

`.github/workflows/ci.yml`'s `check` job runs `pnpm check`, which runs `docs:check` and `docs:lint` after `content:check` ([Content layer](../content/content-layer.md)). `docs:index` is not part of `check`: it's a generator run on demand, not a gate.
